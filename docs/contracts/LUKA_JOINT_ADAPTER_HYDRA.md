# Joint adapter Hydra artifact contract v1

Authority: [active plan](../plans/LUKA_JOINT_ADAPTER_HYDRA_PLAN.md).
All new artifacts are `LUKA_JOINT_ADAPTER_HYDRA_<KIND>/v1`, schema1, canonical
content hashes, exact parent hashes and existing ALLJETS exploratory flags.
Old frozen-adapter scientific artifacts are never relabelled or resumed.

SPEC binds the fixed two-teacher/twelve-student grid, recipe, source snapshot,
input bundle/delta, precise environment and completed Hydra portability evidence.
CONTROL_REFERENCE binds the original4b9630fa campaign spec by file hash and
source commit. Available controls are authenticated by their own original code,
exact-job receipts, checkpoint/prediction file hashes and recomputed metrics.
Absence of a completion receipt means pending, not reusable; no control retrain.

TRAINING_REPORT binds prepared population, recipe, spec, embedding bank for all
students, and selected teacher report for each correction-supervised student.
It declares from-scratch initialization and joint backbone training. Teachers
are privileged oracles; only teacher TRAIN/validation forwards accept U100.
Selected teacher checkpoints include the trained backbone and adapter. Student
checkpoints exclude embedding heads and auxiliary-only correction heads.
FIT records selected checkpoint, prediction/report hashes and verified reload.
EPOCH records full validation and loss/schedule evidence; live previews are
provisional until final FIT/TASK authentication. Original50k is report-only.

SETUP/ACCEPTANCE binds real GPU/environment identity, fourteen one-epoch
production-kernel miniatures and measured memory/time. TASK receipts bind each
task's artifacts to its exact accepted scheduler ID. Invalid inputs, stale code,
nonfinite math, inconsistent populations and incompatible lineage fail closed.
Finite low AUC, weak privileged targets or worse recovery are reportable results.

REVIEW binds a setup plan and full science envelope. Science uses measured
durations within that envelope. A complete exact dry plan precedes submission;
exclusive live claims and immutable intent/acceptance journals prevent retries
after ambiguous scheduler responses. `finish` reuses only successful exact setup
evidence and the original authorization; a complete science ledger is idempotent,
while an active/partial science claim stops for inspection. Never remove claims
or edit an immutable spec to recover a run.
