# HCWDL TRI100 Four-Spine Attention Re-optimization Contracts

The Phase-I persistent-HLT attention campaign uses the prefix
`HCWDL_TRI100_FOUR_SPINE_FULLCARD_PERSISTENT_HLT_ATTENTION_REOPT` and publishes
distinct version-1 graph, recipe, campaign-specification, command-plan,
parameter-lock, execution-acceptance, training-report, selected-checkpoint,
final-checkpoint, probability-stage, aggregate, completion, monitor, and
recovery-specification contracts.

The campaign is a controlled derivative of the corrected full-cardinality
persistent-HLT four-spine experiment. It retains the same authenticated
foundation, altered `SP4P_U000`, support policy, four paths, coordinates,
fresh initializations, C25/P75 temperature-2 logit objective, batch size, and
single-GH200 execution. Its one changed scientific variable is the registered
attention rescue applied at every downstream rung.

Every downstream training report must bind:

- exactly 60 Stage-0 passes, 15 Stage-A passes, and 25 Stage-B passes;
- the installed-Weaver semantic parameter registry;
- the immediate-parent selected report/checkpoint as both probability teacher
  lineage and live relational carrier lineage;
- the support-aligned all-eight-block residual-delta Gram objective;
- zero durable dense relational-target bytes, no rolling resume, and no
  optimizer-state artifact;
- selected and final checkpoints, with Stage 0 remaining eligible for final
  selection when rescue is scientifically worse.

The parameter lock is compiled by module ownership. Stage A exposes only the
canonical pair embedding and all eight particle self-attention modules; name
substring selection is forbidden. Stage B exposes the complete ordinary
student. The teacher remains in evaluation mode with gradients disabled.

Dense teacher block surfaces are generated in the consuming fit, per batch,
and remain in RAM/device scope. The only durable teacher banks are the compact
15-class probability banks already required by logit KD. Completion fails if
an attention-target, block-delta, rolling-resume, or optimizer-state artifact
is present; finite weak metrics remain valid science.

Live execution is two-phase. The three-task authenticate/support/preflight
gate must complete and publish valid task attestations, persistent-support
audit, installed-Weaver parameter lock, and genuine single-GH200 execution
acceptance before the 58-task science plan can be submitted. The resulting
gate and science ledgers are merged into one exact 61-task campaign ledger for
monitoring and source-pinned restart-zero recovery.

No final-test capability is available to ordinary tasks, and the comparison
persistent campaign remains read-only and nonblocking.
