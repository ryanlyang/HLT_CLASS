Default validation source is the original frozen-adapter delta, authenticated
with `LUKA_FROZEN_ADAPTER_HYDRA_TRANSFER/v1` through its original validator.
It is not relabeled as a new TRANSFER. Its location/hash are derived from the
original teacher-sweep's authenticated Group A **cross-message parent**, using
`group_a.parent_spec` and its content-hash binding. Group A's direct delta is a
contrastive-key transfer and must never be substituted. Both parent files,
contracts, content-hash links, populations and shared bundle/reference/imported/
anchor fields are checked before the original frozen-adapter validator runs.
This corrects input-source resolution; scientific semantics and schemas remain v1.
A new selective TRANSFER
is an explicit recovery alternative, not a fallback for corruption.

Training reads only D000 for students. Teacher caches replace whole registered
groups using D000/U100 caches with identical particle offsets, IDs and labels.
All remaining groups are bitwise D000. Teacher validation may use its own
privileged view solely for selection. No validation target bank is exported.
The inference state contains only `mod.*`, exactly the native classifier.

Normalize each new bank independently with TRAIN FP64 mean/population std,
floor .001; standardized payload is FP32. Every student retains the original
U100 bank and predictor seed. Extra heads are independent 128→128→128 MLPs
with GELU. Total extra coefficient is exactly5 split equally, on per-head mean
SmoothL1(beta1). Detached teacher targets cannot receive gradients. New banks
cannot be substituted for the existing OFFLINE bank or for a different field.

Setup acceptance requires all12 profiles, finite positive timings, original
installed environment and RTX A6000 identity, host peak below85% of32000MiB,
GPU peak below88% of device memory, and each projected fit within2880 minutes.
Requests use2× estimated work plus overhead; measured time is the only allowed
change from the original upper-bound DAG. No accuracy/recovery threshold exists.

Bootstrap is GPU setup → CPU release. Release authenticates successful exact
setup accounting, receipts and measurements, then submits four independent
teachers, the eight students in table order with only required teacher
dependencies, and an afterany CPU report. Exact-ID immutable journals and
exclusive claims prevent blind retries. Report/release accept Hydra's observed
one-requested/two-allocated CPU rounding while requiring the exact requested
memory/task/partition/account/QOS and zero GPUs.
