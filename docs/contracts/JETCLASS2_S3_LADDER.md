# Frozen S3 ladder contracts

Authority: [scientific plan](../plans/JETCLASS2_S3_LADDER_PLAN.md).

New `JC2_S3_LADDER_{KIND}/v1` artifacts: SOURCE, SPEC, VIEWS, INPUT, GRAPH,
PLAN, PREFLIGHT, FIT, REDUCER, SUMMARY, CLAIM. Existing kernel training reports,
probability banks and exact-DAG journals retain their original contracts.
Content hashes, parent hashes, file byte hashes and atomic immutable publication
are required. Historical source files/specs/banks must not be edited.

SPEC binds the full completed frozen screen, S3 receipt/summary, original
OFFLINE control and reducer, population, graph, new source and site. A genuine
new preflight binds full endpoint digest equality, installed parity, full KD
acceptance, reducer timing, memory and actual execution environment. Old CE-only
screen acceptance alone cannot authorize this new KD workflow.

New training reports bind the view identity, node, full recipe and selected
weights. FIT binds its actual teacher receipt, preflight and spec. REDUCER binds
the exact selected teacher checkpoint/report, train-only temperature-2 bank and
ordered identities. Validate upstream provenance and payloads even on reuse.
No unavailable or corrupt result is silently treated as valid/pending.

S3 losses are computed on original frozen context at every coordinate; only
surviving valid tracking is interpolated afterward. D000 preparation reuses
the unchanged screen implementation and checks its saved train and validation
digests. Final-test roles fail before file reads. No construction or offline
features enter a deployable D000 tensor. Cached views are RAM-only.

Both dry/live stages require exact source and reviewed plan. Claims refuse
ambiguous partial submission or partial worker output. No broad job mutations.
Missing complete prerequisites/corruption fail closed; poor metrics do not.
Summary requires all four new fits. Partial results may be printed, never used
to prune remaining registered jobs. Development selection and repeated use of
validation must remain disclosed.
