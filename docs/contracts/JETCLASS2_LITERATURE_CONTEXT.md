# Context coupled literature pilot contract

Authority: [context pilot plan](../plans/JETCLASS2_LITERATURE_CONTEXT_PILOT_PLAN.md).
Artifacts use `JC2_LITERATURE_CONTEXT_{KIND}/v1`, schema_version 1, canonical
content hashes, byte-pinned parent references, clean source lineage and atomic
publication. Kinds: RECIPE, INPUTS, SPEC, PLAN, FILE_REPORT, REPORT, RECEIPT,
LEDGER. The inherited calibration keeps its original count38 v2 parents.

SPEC binds the completed count38 training-only pilot, original saved physical
input records/population, calibration, explicit new recipe and resource envelope.
No classifier, CMS response optimization, new count calibration, raw ROOT,
native HLT, validation or final-test particle access is allowed. Source/resource/
parent drift, nonfinite physical values and replay failures are execution errors;
scientific quality is never a job gate.

Each new bank contains identity and, for NOISE_V3, LOW_NOISE and CONTEXT, offsets,
p4, charge, category, tracking and validity arrays in the original GeV/mm schema.
OFFLINE remains in the authenticated ancestor. Identical ancestry, keys, PID,
validity, charge and multiplicities are required across controls. CONTEXT also
preserves LOW_NOISE p4 exactly. Diagnostic lineage is stored separately and is
forbidden as a feature or undeclared oracle matching supervision.

Context uses only exposed post-response p4, not hidden generation inputs. The
raw map has an explicit inverse on complete tracking; missing tracking is
unchanged. No guarantee is made about detector fidelity, standard-deviation
meaning of transformed scales, or exact float32 information conservation.
INPUTS versions the optional unclipped tracking encoding; old 17-input science
is unchanged. New-front-end reconstruction and old-front-end saturation are
reported separately from raw inverse replay.

RECEIPT is published last and seals the exact set of per-file reports, physical
banks, diagnostic lineage, inherited calibration, combined report, CSV and PDF.
Existing completed outputs authenticate before reuse; failures retain locks for
inspection. PLAN is one CPU-only Tigris job, dry by default, requiring its exact
reviewed hash and `AUTHORIZE JC2 LITERATURE CONTEXT PILOT EXACT PLAN` for live
submission. No full generation or automatic classification followup exists.
