# LUKA_EMBEDDING_SWEEP_* / v1

Authority: [extended sweep plan](../plans/LUKA_EMBEDDING_SWEEP_PLAN.md).

Separate versioned namespace, never interchangeable with the original
three-weight LUKA_EMBEDDING_WEIGHT_*/v1 artifacts. Canonical hashes, exact
parents, source snapshots and explicit exploratory/no-independent-test flags
are required. Ordered arms: w3,w5,w20,w50,w100,w200,w500,w1000.

- RECIPE binds CE coefficient1 and exactly one registered auxiliary weight,
  unchanged original target-recipe hash, schedule, normalization and predictor.
- GATE binds original matched M0HLT/OFFLINE anchor, completed0.3 target import,
  all eight nodes, exact tier3 registration and2GiB persistent allowance.
- ARM binds one node/recipe to that gate. Scientific models are fresh and
  independent; technical artifacts cannot substitute for science.
- TRAINING_REPORT/FIT bind recipe, bank, identities, native selected state,
  full-val selection, complete30-epoch history and validation predictions.
- PREFLIGHT contains installed/native/zero-weight parity, eight full technical
  epoch roundtrips and per-weight TRAIN/validation support stresses, environment,
  GPU identity, positive finite resource evidence and measured requests<=24h.
- SPEC binds accepted gate/report and all eight independently submitted tasks.
- PLAN/claim/exact journal bind the reviewed commands and
  `AUTHORIZE_LUKA_EMBEDDING_SWEEP_V1`; only exact COMPLETED/0:0 gate accounting
  admits science. No automatic retry after uncertain submission.
- SCIENCE/RESULTS bind outputs and recomputable CE/OFFLINE/0.3 comparisons.
  An incomplete arm is pending, not a completed result. Reporting needs retained
  local evidence but not model deserialization or the old particle arrays.
- FOLLOWUP_PLAN binds the exact gate plan, eight-arm science ceiling plan,
  source, 24h per-fit bounds, 60s polling, 14day wait limit and distinct
  `AUTHORIZE_LUKA_EMBEDDING_SWEEP_FOLLOWUP_V1`. Placeholders in the ceiling
  are review-only and never executable. FOLLOWUP_AUTHORIZATION records the
  explicit approval; an atomic permanent live claim prevents duplicate
  controllers. The GATE's default `automatic_followup=False` means no implicit
  launch and is not edited to opt in.
- FOLLOWUP_ARMED binds the exact accepted gate ledger/job. Only matching
  numeric ID, `lukaes_preflight`, owner, account and COMPLETED/0:0 permits full
  receipt/source/resource validation; successful scheduler state alone is not
  admission. FOLLOWUP_REVIEW binds the measured spec and saved exact dry plan;
  only its spec hash and eight admitted walltimes may differ from the reviewed
  ceiling commands. FOLLOWUP_COMPLETE requires all eight exact journal/ledger
  entries; `training_complete=False` distinguishes queued from trained.
  FOLLOWUP_FAILURE preserves the error and prohibits automatic retry. Existing
  science roots and ambiguous submissions cannot be adopted by the controller.

Shared target BANK remains AUX/v1 with original0.3 target-construction recipe;
that provenance coefficient is not the new student's coefficient. Ordered
TRAIN identities/labels must match. Source pin rejects edits to existing runtime.
Root overlap with source/shared artifacts is forbidden. No automatic deletion.

Both preflight and science use tier3/A100,6CPUs/90000MiB, same installed
environment as the original controls. An old debug or three-weight gate,
even rehashed, is rejected; it cannot replace new eight-weight acceptance.
