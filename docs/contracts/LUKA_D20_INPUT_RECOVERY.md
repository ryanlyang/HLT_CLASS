# Full D20 targeted input recovery contract

The owned `LUKA_D20_INPUT_RECOVERY_*/v1` namespace is an execution-only adapter
for the immutable `d20_full_5af66449_r1` study. It preserves original science
source, runtime, recipe, population, starts, teachers, target normalization,
selection, batch256, FP32 and restart state. Deployable inference remains
HLT-only and final-test inference stays sealed.

SPEC/v1 binds exact clean pushed repair source, original spec/qualification/task
references, the successful qualification job, explicit failed root task/job IDs
and POLICY/v1. It never mutates an old spec or source. A completed qualification
can be reused only after a real CPU READER_PARITY/v1 job finishes successfully.
The probe replays authenticated original scalar membership and compares both
reader paths on authorized TRAIN/validation spans in the timed-out QCD file
and a signal file: D000, OFFLINE and U100, with TRAIN-only reconstruction targets.
Native arrays, identities, mixed targets, validity, frames and aggregates must
match exactly; no model is updated. Source bytes are hashed before and after.

The replacement Reader changes only construction of the physical ROOT source:
one native Uproot local file handle with threads disabled. Original bounded
basket-cache and numeric interpretation methods remain inherited from the
original source. No full-file particle arrays or durable particle cache is added.

The owned decoder preserves each accepted prefix and canonical accept order.
A timeout or explicitly listed transient I/O errno can restart only its owned
pool, at most twice. It replays the failed and outstanding unaccepted batches,
with source-checksum verification inside the monitored worker before each
replayed batch. No row is skipped, duplicated in published data, or reassigned.
Invalid data, nonfinite values, checksum mismatch, missing files and permission
failures are never retried. A pool that cannot be reaped within15s aborts the
allocation instead of attempting more work; OS/Slurm still owns process cleanup.

Scheduling uses exact immutable root jobs and the original DAG. Only failed
roots and their unfinished descendants are replaced; completed receipts and
unrelated active jobs remain. Active scientific descendants block recovery.
Only exact campaign-bound PENDING descendants may be cancelled, after a fresh
scontrol check and using `scancel --state=PENDING ID`. A started job is preserved.
The report is rebound to new replacement IDs and original unrelated IDs.
Every actual batch script is dry-reviewed before live actions. Writer locks,
intent-before-action and response/accepted journals reject duplicates and
uncertain submissions. No broad job-name cancellation is allowed.

Replacement submissions are appended in original accepted-journal format,
carrying `execution_recovery` and a checksummed `execution_spec`. Original worker
allocation guards still validate task/job/comment/resources and original WorkDir.
Each replacement also publishes EXECUTION_OVERRIDE/v1 binding the repair policy
and parity proof. Scientific epoch parents remain unchanged to allow exact
restoration of existing committed model/decoder/AdamW/RNG state; the accepted
job ID links every new epoch to the explicit technical override. No earlier
artifact is silently relabelled or rehashed.

The bootstrap probe uses4 CPUs/32,000MiB/4h; release uses1 CPU/4,000MiB/1h.
Replacement science retains4 GTX1080Ti/12 CPUs/96,000MiB/48h. This repair does
not reserve a second full scientific-output allowance or add automatic HOME
checks. Existing full-support GPU startup, per-allocation miniature and source/
payload checks remain active. Persistent filesystem failures can still abort
the bounded retries; a local test does not prove Hydra filesystem availability.
