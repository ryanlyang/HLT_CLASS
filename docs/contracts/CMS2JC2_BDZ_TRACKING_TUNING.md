# CMS2JC2 B_DZ tracking tuning v1

Authority: `docs/plans/CMS2JC2_BDZ_TRACKING_TUNING_PLAN.md`.

All artifacts use the existing `CMS2JC2_RESPONSE_` prefix, `/v1`, canonical
content hash, explicit parent hashes and `final_test_accessed: false`.
New kinds: `BDZ_PROTOCOL`, `BDZ_STAGE`, `BDZ_REUSE`, `BDZ_MAP`,
`BDZ_ACCEPTANCE`, `BDZ_REGISTRY`, `BDZ_SHARD`, `BDZ_SELECTION`.

Stages bind their exact task/resource registry, protocol, study and parent file
hashes. The gate imports completed B_DZ development selection without editing it.
The comparison binds the completed calibration, all three candidates, fixed
replicas and sample membership. Receipts authenticate every reusable file.

Maps bind the historical B_DZ model and calibration sample hash; per-coordinate
PID and pooled cells record contributing unique-jet counts, quantile knots,
identity/unsupported status and selected fallback. Arrays must be finite and
monotone; source knots strictly increase. There is no raw durable particle array.

Workers enforce unchanged p4, keys, PID, charge and validity, including exact
historical control replay on the evaluation population. Calibration cannot access
evaluation or confirmation. Evaluation cannot fit or alter maps. Reports bind all
shard hashes, the chosen strength and the calibration map, retain rejected rows,
and explicitly deny production qualification, confirmation access and transfer.

Numerical quality is a result. Broken identity, source drift, invalid particles,
nonfinite data, unsafe paths or incomplete population coverage fail closed.
The old bounded v1 contracts and scientific code remain unchanged.
