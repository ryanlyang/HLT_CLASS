# B_DZ significance audit debug replacement v1

Authority: docs/plans/CMS2JC2_BDZ_AUDIT_DEBUG_REPLACEMENT_PLAN.md.

Additive CMS2JC2_RESPONSE v1 kinds: BDZ_AUDIT_DEBUG,
BDZ_AUDIT_DEBUG_REUSE, BDZ_AUDIT_DEBUG_RETIREMENT. All retain content/parent
hashes, immutable atomic publication and final_test_accessed=false.

The new stage binds a debug study, the original tier3 audit specification,
acknowledged ledger/journals, completed original acceptance/report receipt,
unchanged protocol, source, numerical environment and frozen B_DZ comparison.
There are four independent 36-CPU/128-GiB/eight-hour shards and a
one-CPU/32-GiB/four-hour report depending on the four new IDs.

Original ba_acceptance is reused read-only, not rerun, relabelled or republished.
Its original hash is the acceptance parent of the new report. New shard/report
artifacts retain BDZ_AUDIT_SHARD/REPORT v1 and bind the new stage hash. Their
scientific fields and diagnostic-only qualification flags are unchanged.

Retirement requires exact authorization, reviewed plan, debug admission,
COMPLETED/0:0 original acceptance, authenticated pending-job identities and
pending-only controller cancellation. Original evaluation/report claims or
receipts, active/successful/unknown states and ambiguous journals fail closed.
Post-cancel accounting must show all five exact targets non-success terminal.
Live submission rechecks retirement state; workers validate its immutable
evidence and original acceptance/source lineage before claiming work.

No frozen model/map, original output, other campaign or scientific selection
changes. This registration does not qualify the response or promise runtime.
