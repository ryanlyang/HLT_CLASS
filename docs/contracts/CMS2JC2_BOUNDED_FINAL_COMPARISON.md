# CMS2JC2 bounded final comparison v1

Authority: [bounded comparison plan](../plans/CMS2JC2_BOUNDED_FINAL_COMPARISON_PLAN.md).

Additive `BOUNDED_*` artifacts use CMS2JC2_RESPONSE_* /v1, canonical content
hashes, named parents and final_test_accessed=false. New kinds distinguish
protocol, stage, model wrapper, acceptance, calibration, registry, shard,
selection, confirmation memberships, confirmation claim and final report.

The protocol rederives fixed candidates/grid/scores/populations at validation.
Derived models bind original B/C hashes and recipe; rebuild-and-compare prevents
edited modules being reused as frozen candidates. Existing FITTED_RESPONSE
runtime machinery remains unchanged and original artifacts are read-only.
Scientific source import permits only the existing execution-only exceptions.

Gate and comparison read response_fit only. A separate bounded confirmation
reader requires authenticated immutable selection, canonical 20k membership,
stage-bound claim and exact confirmation-role files. It must not broaden the
old development reader, forge a production SELECTION, or relabel this as the
full three-family confirmation. Labels, JC2 and historical validation/test
particles are unavailable. Claims and separate authorization precede reads.

No scientific-quality failure is an execution failure. Invalid data, nonfinite
required metrics, role/source/environment mismatch, missing receipts, changed
protocol or corruption fail closed. Poor/missing support is counted and all
jets retained; unavailable distributions receive the registered explicit score.
No positive diagnostic may publish production_qualified=true.

Exactly three fixed stages; comparison and confirmation are never automatically
submitted. No API adjusts the grid or selects again after confirmation. Exact
same-source technical retry requires a new separately reviewed execution design,
not overwriting failed claims/results. Dataset transfer remains outside scope.
