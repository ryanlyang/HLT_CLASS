This family is `NOISE_V3_K2_*/v1`, not an interchangeable version of native

## Data, formula and features

`CAMPAIGN_SPEC` binds a clean, locally known pushed commit and its exact checkout,
separate output root, fixed frozen manifest, relocated metadata description,
ordinary-role shard registrations, formula import, model/view/training/resource
registrations and full DAG. It exposes no arbitrary count, recipe, batch, site,
final-test or matching-candidate override.

`FORMULA_IMPORT` requires the unchanged original full K2 v7 campaign JSON and
its independently recorded raw SHA256. Authenticate the embedded spec,
foundation, source-import identities and exact old matcher definition. Import
only that formula; never traverse the copied JSON's RIT paths. Do not import a
one-to-one map, K2 map, model, timing, population or acceptance from that source.
The new physical validity-aware `VIEWS` definition gets a separate hash.

`POPULATION` binds the immutable consumer spec and frozen manifest. Stratify
the original ordinary roles by label, use natural Hamilton quotas and canonical
identity SHA256 ranking, then restore source order. Exactly 100k train and 50k
validation. Labels are targets/selection metadata only. Validate original
eligibility scalars, tree identity and raw entries; never use native HLT particle
branches. Selected memberships store uint8[rows,32] IDs, int64 labels/entries,
int32 shard indices and validation uint8 partition codes. Hash-order each class
into checkpoint/diagnostic/report 50/25/25; require >=4 rows per class. Counts
can differ slightly from ideal percentages due per-class rounding.

Proxy blocks retain original byte checksums, physical schemas, order and every
canonical identity, even when only selected rows are decoded to particle
objects. Paired ROOT reads authenticate bytes before and after access and read
offline particles in bounded 512-entry buckets. Original GeV/mm and explicit
tracking validity remain intact. Final-test role fails before particle I/O.

`ASSIGNMENT` binds consumer/population/shard and compact array bytes. Each row
has exactly Nproxy x2 signed-int32 native offline indices or -1. Retain the top
min(Noffline,2*Nproxy) salience entries with native-index ties, before exact
integer assignment. Freeze salience on complete endpoints, never renormalize
after truncation or destination duplication. Occupied slots are canonical,
unique and maximum-cardinality. Rich-slot fillers are active proxy copies.

Each selected jet is checked at every rung for 3*Nproxy support, unchanged
original proxy slots and finite 17-feature construction. Per-shard diagnostics
include cropping, pT/salience loss, occupancy, distances and class counts.
`MATCHER_ACCEPTANCE` compares bounded real subproblems to the independent
exhaustive reference (at most four destinations/offline entries), across all
classes. It also checks deployment preprocessing. Low teacher/recovery scores
are never acceptance criteria.

`FOUNDATION` binds every ordinary assignment and population. Derive no-truncation
capacity from selected ordinary maxima only, rounded up to16, covering original
offline and expanded proxy x3. Cache bounds must fit the registered RAM fraction.
Features use the own-view axis/scales; no source/index/slot/ancestry indicators.
D000/x3 and x1 read proxy banks only, not ROOT or matching. Both deployments are
HLT-like proxy-only, not a claim of real-CMS response qualification.

## Execution and outputs

Exact source and OSCAR allocation checks run before workers. CPU jobs use batch;
GPU jobs use gpu/norm-gpu, one L40S. Resources are immutable requested envelopes,
not claims of measured permission. Live submission checks `sbatch --test-only`
for each resource shape. A scheduler rejection publishes no submission claim.

`ACCEPTANCE` is produced only by the registered native GPU preflight. It binds
spec/foundation/site/environment/GPU, selected capacity/counts and batch128.
Cases: D100, D075, D000, compressed x1, and pure offline. Each case builds full
selected caches, stress-trains the longest real batch with three AdamW steps,
runs a two-pass native production-kernel CE/KD miniature, and verifies saved
selected weights and T2 bank round trips. D100 and x3 also require native Weaver
forward/backward and FP32/BF16 saved-tensor-storage parity. Preserve timings and
measurements on rejected admission. Require finite timings, at most 90% GPU /80% RSS,
<65% RAM caches and conservative max-fit projection <=23h under a24h request.
No CPU fake, missing case, old SPORC gate, silent batch reduction or unregistered
shortened run can authorize science. Real OSCAR parity remains mandatory.

`TRAINING_REPORT` binds node/spec/population/foundation, original full recipe,
teacher bank/receipt, selected checkpoint SHA and separate checkpoint/report
metrics. The ten fits are cold initialized with the original paired seeds.
Reducers publish T2 probabilities for every ordered training identity using the
existing authenticated compact bank contract. A miniature report cannot be a
teacher. `DEPLOYMENT` exports checkpoint provenance and physical proxy-only
preprocessing (three copies or one); it cannot include offline/matching inputs.

`TASK` is published last, with exact parent receipt hashes and all output byte
hashes. Every dependent worker authenticates its ancestors. Partial results use
only completed authenticated training reports and validation REPORT metrics.
Recovery is linear metric-space HLT_X1_CE=0%, OFFLINE_CE=100%; censored R50 and
zero recovery denominators remain null. Aggregation never opens final test.

## Submission and limitations

Create produces full/gate/science dry ledgers. Live full-DAG submission is
forbidden. Exact phrase `AUTHORIZE OSCAR NOISE V3 K2 100K 50K EXACT SPEC` admits
the gate; `--auto-science` additionally permits after_gate to submit the17
science tasks only after authenticating fresh acceptance. Without that flag,
the user must explicitly submit science. Completed gate artifacts replace
expired cross-stage Slurm IDs; scientific dependencies use exact afterok IDs.

Acknowledged jobs are journaled before continuing. An exclusive stage claim
prevents replay after an ambiguous scheduler acknowledgement. A completed live
ledger is idempotent; a partial claim requires an exact-ID review. No broad
cancellation, automatic retry/requeue, cross-site partition mutation or mutable
campaign repair is implemented. Failed tasks keep diagnostic artifacts, never
publish completion, and block downstream work. Resource changes require a
reviewed new registration; old SPORC segmented resume is not part of this port.
