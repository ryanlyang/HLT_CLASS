# B_DZ significance audit v1

Authority: `docs/plans/CMS2JC2_BDZ_SIGNIFICANCE_AUDIT_PLAN.md`.

Additive CMS2JC2_RESPONSE v1 kinds: BDZ_AUDIT_PROTOCOL, BDZ_AUDIT_STAGE,
BDZ_AUDIT_REUSE, BDZ_AUDIT_ACCEPTANCE, BDZ_AUDIT_SHARD, BDZ_AUDIT_REPORT.
All have canonical content hashes, explicit parent hashes, immutable atomic
publication and final_test_accessed=false. Existing BDZ_* kinds are unchanged.

Stage binds protocol, exact task registry, fresh study, completed parent and
reuse evidence. Reuse binds original selection, calibration registry and
receipt hashes. New study retains the original scientific source, numerical
environment, samples and units. Source or membership differences fail closed.

Audit shards bind new stage/protocol, parent shard hash, calibration map,
sample/range hashes, ordered identity digest, full population count and replay
verification. Payload cells are source/side/PID dictionaries with moments,
fixed histograms, validity states, joint moments and bounded forensic examples.
Sides are real or candidate/replica, never independently resampled jets.
Ratios require both valid value and positive valid uncertainty; zero values
are valid and logarithmic zeros are counted explicitly, not discarded.

The report authenticates all four new shards and acceptance, includes their
hashes and the unchanged historical selected candidate, and explicitly sets
confirmation_accessed, production_qualified, transfer_authorized and
automatic_followup to false. It computes no new winner or candidate score.
Bounded examples include hashes rather than source event identities. Existing
models/maps, output artifacts and scheduler jobs remain read-only.
